# secure_ai_agents — лабораторная «Защищаем ИИ-агента»

Продолжение лабораторной [common_ai_agents](https://github.com/Psyhoved/common_ai_agents) и практика к занятию
«Как построить ИИ-приложение, которое трудно взломать» (Security by Design).

Вы получаете бота, который ищет в базе знаний и в интернете, читает файлы и отправляет письма. Бот собран
небрежно: его можно уговорить выдать закрытые данные, открыть чужую ссылку или потратить весь бюджет.
Ваша задача — закрыть дыры по семи слоям защиты и доказать это тестами и набором атак.

Письма, команды и файлы в лабораторной не настоящие: каждое действие записывается в учебный «мир»
(`bot/world.py`), и атаку можно проверить кодом.

## Быстрый старт

**Шаг 1. Скачайте репозиторий и установите зависимости.**

```bash
git clone https://github.com/Psyhoved/secure_ai_agents.git
cd secure_ai_agents
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

**Шаг 2. Посмотрите, как бот ломается.** Ключи и сеть не нужны: по умолчанию работает учебная имитация модели.

```bash
python scripts/run_attacks.py
```

Вы увидите, что удались все 13 атак.

**Шаг 3. Откройте `lab_notebook.ipynb`** (`jupyter notebook lab_notebook.ipynb` или Google Colab) и идите по заданиям.
В каждом задании откройте файл из папки `student/`, прочитайте задание в начале файла и замените заготовки
на свой код. Проверка:

```bash
pytest tests/test_01_input.py        # задание 1; остальные — test_02 … test_07
pytest                               # все тесты сразу
```

**Шаг 4. Прогоните набор атак на готовом боте** (`python scripts/run_attacks.py`), затем на живой модели
(следующий раздел).

## Подключение модели

Тесты и набор атак на имитации (`mock`) проходят без сети. Для финального прогона на живой модели выберите вариант,
который работает в вашей стране. Скопируйте `.env.example` в `.env` и заполните нужный блок. Все варианты
используют один и тот же клиент: бот и тесты не меняются.

| `LLM_PROVIDER` | Что это | Что нужно |
|---|---|---|
| `mock` | Учебная имитация. По умолчанию | ничего |
| `openrouter` | Как в `common_ai_agents`: бесплатные модели, выбираются автоматически | `OPENROUTER_API_KEY` |
| `ollama` | Модель на вашем компьютере, без интернета и ключей | установленный [Ollama](https://ollama.com), загруженная модель с поддержкой tools |
| `lmstudio` | То же через [LM Studio](https://lmstudio.ai) | запущенный локальный сервер, загруженная модель с поддержкой tools |
| `custom` | Любой сервис с OpenAI-совместимым API | `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` |

**Если OpenRouter у вас не открывается.** Есть два пути.

1. *Локально.* Установите Ollama или LM Studio, загрузите любую модель с поддержкой вызова инструментов (в каталоге
   Ollama есть фильтр по tools), поставьте `LLM_PROVIDER=ollama` (или `lmstudio`). Модель подхватится сама, имя можно
   указать в `LLM_MODEL`. Небольшие модели хуже следуют инструкциям, поэтому атаки на них удаются чаще, и это нормально.
2. *Другой облачный сервис* через `LLM_PROVIDER=custom`. Подойдёт любой, у которого есть OpenAI-совместимый
   API. По их документации на момент проверки (2026-11-14), например:
   `https://api.groq.com/openai/v1`, `https://api.together.xyz/v1`, `https://api.deepseek.com`, `https://api.mistral.ai/v1`.
   У российских облаков (например, Yandex AI Studio, Cloud.ru) тоже есть совместимые API: адрес и название
   модели берите из их документации. Доступность из вашей страны, условия и цены проверяйте сами: они меняются.

Проверка подключения:

```bash
python -c "import llm; print(llm.make_llm().name)"
python scripts/run_attacks.py --provider ollama --repeat 3
```

Настоящая модель отвечает по-разному от запуска к запуску, поэтому каждую атаку повторяют (`--repeat`) и считают долю успехов.
Бесплатные модели и их лимиты меняются: если OpenRouter отвечает ошибкой 429, подождите или переключитесь на локальную модель.

## Как устроена проверка

- `tests/test_01…07` проверяют каждый слой отдельно, а в конце файла есть сквозные тесты через бота.
- `tests/test_08_attack_suite.py` — критерий выпуска: доля удавшихся атак не больше 10 %, обязательные атаки
  (помечены в `attacks/attacks.yaml`) не удаются ни разу.
- Имитация модели доверчива: она исполняет инструкции из документа, не помеченного как данные, и
  вызывает любой инструмент по просьбе пользователя. Это упрощение для проверки кода. Живая модель
  ведёт себя сложнее, поэтому задание 8 включает прогон на настоящей.
