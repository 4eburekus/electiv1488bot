# ИИ-агент консультант в Telegram

Бот отвечает на вопросы про ИИ-агентов по 14 учебным PDF и по актуальным новостям.
Модель сама решает, чем пользоваться: базой знаний, веб-поиском или и тем и другим.

```
Пользователь в Telegram
  → telebot (bot.py)
    → create_agent: ReAct-цикл think → act → observe → answer
      ├── @tool search_knowledge_base → Chroma + реранкер → фрагменты PDF
      └── @tool search_web            → DuckDuckGo → заголовок, ссылка, сниппет
    ← ответ, нарезанный split_message под лимит Telegram
```

## Структура проекта

```
electiv1488bot/
├── bot.py                       телеграм-слой + агент
├── check_agent_offline.py       офлайн-проверка без Telegram и внешних API
├── tool_rag/
│   ├── rag_indexing.py          индексация PDF в Chroma (запуск один раз)
│   └── rag.py                   поиск по базе + @tool search_knowledge_base
├── tool_web_search/
│   └── web_search.py            DuckDuckGo + @tool search_web
├── knowledge_sources/           14 PDF (вне git)
├── chroma_db/                   векторный индекс, 647 чанков (вне git)
├── myvenv/  .env                окружение и настройки (вне git)
└── *.orig.py                    копии файлов до правок — сравнение и откат
```

Все настройки бота описаны комментариями прямо в `.env` — в README их не дублирую.

## Запуск

```
myvenv\Scripts\python.exe -m pip install -r requirements.txt
myvenv\Scripts\python.exe tool_rag\rag_indexing.py     # собрать индекс (нужен только раз)
myvenv\Scripts\python.exe bot.py                        # поднять бота
```

Нужен запущенный локальный сервер эмбеддингов — им пользуются и индексация, и поиск.
Бот прогревает Chroma и cross-encoder на старте, поэтому первый вопрос стоит ~3 с
вместо ~13 с.

## Этапы, которые уже собраны

1. LLM: `ChatOpenAI` с `request_timeout=120` — без него зависший роутер ждёт 600 с.
2. Извлечение текста: по каждому PDF сравниваются `PyPDFLoader` и `PDFPlumberLoader`
   по штрафу за искажения — берётся чище.
3. Чанкование: `RecursiveCharacterTextSplitter`, `chunk_size=800`, `overlap=150`.
4. Эмбеддинги: `bge-m3` через локальный API-сервер.
5. Индекс: `Chroma` (коллекция `rag_educational_collection`), ключ чанка — хеш файла,
   страницы и текста; при открытии сверяется модель эмбеддингов — чужой индекс не подмешается.
6. Реранкинг: `BAAI/bge-reranker-base`, кэшируется на процесс.
7. Веб-поиск: `DuckDuckGoSearchAPIWrapper`, ретраи, `SEARCH_TIMEOUT=30`.
8. Агент: `langchain.agents.create_agent` с `tools=[search_knowledge_base, search_web]`.

HyDE и multi-query в `rag.py` остались нетронутыми для офлайн-экспериментов, но бот их
не вызывает: лишний запрос к LLM на 10–90 с не подходит чату.

## Поведение бота

- Инструменты всегда возвращают строку и не бросают наружу: при недоступном источнике
  ответ начинается с ⚠️, и промпт требует честно сказать об этом, а не выдумывать.
- Поиск по базе отдаёт фрагменты `[N] файл.pdf стр.X` — в ответе есть ссылки на источник.
- Ответы длиннее 4000 символов режет `split_message`: по границам строк, с сохранением
  абзацев и закрытием блоков кода на стыке частей.
- Реранкер по умолчанию включает 20 кандидатов → cross-encoder → топ-5; без него поиск
  идёт только по косинусной близости и отвечает быстрее.
- `/start` и `/help` — подсказка; голосовые, фото и документы получают вежливый ответ.
- `load_dotenv()` стоит выше импортов инструментов: `rag.py` читает настройки на уровне
  модуля, иначе не сверить модель эмбеддингов.

Прогон проверяет схему инструментов, ветки ошибок, нарезку сообщений, локальные ресурсы
и `ask_agent`. `--fast` гоняется отдельно: проверяет, что реранкер не загружен на быстром
пути.
